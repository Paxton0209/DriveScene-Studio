# DriveScene Studio · Design Guideline（界面外壳）

版本 v0.1 · 2026-10-31 · 状态：草案；后续执行登记与用户最新要求覆盖原建议，当前实现与验收状态见第 20 节


## 0. 如何使用本文件

* 读者是 Codex（执行者）。Claude 负责方向与验收，用户做最终视觉验收。
* 范围：仅界面外壳，即顶栏、左栏、右栏、控件、画布外框、画布下方控制条。不含 3D 场景渲染（光照、材质、倒影、车辆、天气画面等），那部分仍以《DriveScene 协作与验收规范》为准。
* 优先级：① 协作与验收规范中用户已确认的规则 ＞ ② 本文件 ＞ ③ 参考来源。出现冲突时停下并回报，不自行取舍。
* 标注：【来源】表示来源明确给出的内容；【建议】表示 Claude 给出的目标值，必须实测并按截图校准，不等于最终值。
* 不新增本文件和用户都没要求的元素、说明文字或概念（如无必要勿增实体）。

## 1. 设计目标与原则

一句话：安静的工具面板，把视觉重量让给画布。

1. 不争没挣到的注意力。承担导航和参数的区域要退后，用户工作的区域（画布）优先。Linear 2026 的做法是把侧栏调暗几档、图标缩小、非选中文字变淡、纵向留白加大。【来源】
2. 结构是被感受到的，不是被看见的。减少分隔线和边框，边框要圆角、低对比。【来源：Linear 2026】
3. 中性灰为主，只有一个强调色。Linear 通过限制蓝色参与配色计算，让界面回到更中性、耐看的外观；文字和中性图标在浅色下更深、深色下更亮。【来源：Linear 2024】
4. 对齐就是质感。标签、图标、按钮的横向和纵向对齐，是用上几分钟后才会"感觉到"的细节。【来源：Linear 2024】
5. 控件数量克制。图标和控件的存在感要和它的重要性匹配，必要时减少而不是加样式。【来源：Linear 2026】

## 3. 布局结构

1. 三栏停靠：左栏、右栏贴边、全高，不做浮动卡片；中间是舞台。只有画布外框做内嵌处理（圆角、细边）。
2. 顶栏保持极简：左侧产品名，右侧主题按钮；高度约 40–44；底部用低对比细线。【建议】
3. 左栏顺序：Driving、Parking、Vehicles，车型常驻；互斥标签已取消。shell-hierarchy-3 本地试版去掉冗余的 Scenes 可见标题，导航保留 Scenes 无障碍名称；三个组标题统一 12px/500/次级灰，组间 24px、标题到条目 8px。试版待视觉确认，见第 21 节。
4. shell-hierarchy-3 本地试版右栏按对象组织：当前场景名及参数（如 Road：Lanes、Camera）→ Environment（Weather）→ Layers → Export；去掉 Across scenes 标题。Export 固定在底部，上方保留一条细线。Indoor 隐藏整个 Environment，保留室外天气选择，后续参数上移。本轮分组调整待视觉确认。
5. 舞台：画布居中，四周留稳定边距（宽屏 ≥24，窄屏 ≥16）；画布下方是控制条（Play/Pause，Junction 的声音按钮并入同一条）；泊车未做时控制条不出现，但画布位置不得因此跳动。
6. 画布与对应控件必须同时可见（桌面和窄屏都要检查），不允许操作后必须滚动才能看到结果。【来源：协作规范】

## 4. 尺寸、间距、圆角【建议】


| 项 | 目标 |
| --- | --- |
| 间距基准 | 4px；常用 4 / 8 / 12 / 16 / 24 / 32 |
| 左栏导航行 | 高 32，行间距 2，行内左右内边距 8，图标与文字间距 10 |
| 右栏参数行 | 高 32；标签列固定宽度；控件靠右对齐，右缘统一 |
| 控件高度 | 分段、下拉 28；主按钮 32；图标按钮 28 |
| 圆角 | 6（内层滑块、小标签）/ 8（控件、行）/ 12（画布外框、菜单、卡片）/ 16（仅大型浮层，慎用）；同心圆角 = 外圆角 − 内边距 |
| 分组间距 | 24；组内行间距 4–8；用间距分组，不用横线 |
| 面板内边距 | 左栏容器 8，右栏容器 16 |
| 边框 | 1px 低对比透明度边框；非交互元素（面板、画布外框）用最淡一档 |

参考数值【来源：Apple HIG Sidebars】：中号侧栏行高 28pt、图标 20、文字 13pt；大号行高 32pt、图标 24、文字 15pt；单元格之间纵向间距 0。本项目左栏取 32 行高，因为带彩色图标容器。

## 5. 字体

* 字体沿用现有无衬线（目测为 Inter 类），不新增字体。
* 字号只用 12 / 13 / 14；字重只用 400 / 500；行高约 1.4。【建议】
* 层级：分组标题 12/500/次级灰（不要比条目更深）；控件标签 13/400/次级灰；选项和数值 13/主色；提示气泡 12。
* 不使用小于 12 的字号（HIG 的 macOS 最小值为 10，本项目更保守）。【来源 + 建议】
* 数值读数（如 3840 × 2160）使用等宽数字（font-variant-numeric: tabular-nums），避免切换时抖动。
* 不用大写字母标题，不加字距。

## 6. 颜色

命名沿用十二阶角色【来源：Radix Colors】，每套主题（浅、深）各手写一套，不做主题生成器：

| 阶 | 角色 | 本项目用途 |
| --- | --- | --- |
| 1 | 应用背景 | 舞台背景 |
| 2 | 次级背景 | 左栏、右栏、顶栏 |
| 3 / 4 / 5 | 组件背景：常态 / 悬停 / 按下或选中 | 控件底、选中行；悬停不使用阶 4，见第 8 节 |
| 6 | 非交互的细边框和分隔 | 面板边、画布外框、Export 上方线 |
| 7 | 交互控件的边框 | 下拉、按钮 |
| 8 | 更强的交互边框和焦点环 | 焦点环 |
| 9 | 实色 | 强调色实底（开关开启、主按钮） |
| 11 / 12 | 次级文字 / 主文字 | 标签 / 数值与标题 |

要求【建议】：

1. 中性色略偏暖但不泛泥，不与 3D 场景的冷灰天空混成一团；以相邻时能一眼区分为准。【参考：Linear 2026 的灰色调整思路】
2. 边框、分隔、叠层用黑或白的透明度表达，浅深两套保持同一比例关系。
3. 只有一个强调色：现有路径蓝。用途限定为：开关开启、主按钮、焦点环。其余全部中性。
4. 不用纯黑纯白作大面积底色。
5. 对比度：13px 正文和次级文字 ≥ 4.5:1，非必要的第三级提示可放宽；图标 ≥ 3:1。浅深主题都要测。

## 7. 组件规范


### 7.1 左栏导航行

* 选中：中性灰圆角填充（圆角 8），文字加深；不加描边。
* 彩色图标保留原色相与分类，场景 SVG 占位与车型缩略图槽均为 32×24px，场景底板保持方形比例；车型槽为浅底、6px 圆角。shell-hierarchy-3 对非选中图形做两版减重：A 饱和度 12%，B 亮度 78%，共同透明度 72%；选中恢复原色和 100% 透明度。场景和车型分别强调各自的选中项，试版待确认。
* 非选中文字用次级灰，选中文字用主色和现有中等字重。Driving、Parking、Vehicles 标题统一次级灰、12px、500，不新增分隔线。
* Indoor 与 Outdoor 右下角是房屋、树的场景角标，不能当作状态圆点。2026-10-31 源码核对确认其造型；当前小尺寸的可辨识性待改进和验证，保留彩色图标与角标语义。

### 7.2 分段控件

* 轨道高 28，内边距 2，轨道圆角 8，滑块圆角 6；滑块白色（深色下用抬高一档的灰），带极轻阴影。
* 选中项文字主色，其余次级灰；选中滑块滑动过渡，不跳变。
* 仅图标的分段（Weather）：每项必须有可访问名称和悬停提示，图标 16、线宽 1.5，三个图标需能在小尺寸下区分。

### 7.3 开关

* 约 28×16，圆点 12；开启为强调色，关闭为中性阶 5；圆点滑动。
* 不使用黑色大开关；同一屏内开关不得比画布更抢眼。

### 7.4 下拉与菜单（Format、Size）

* 触发器高 28，圆角 8，细边，常态背景为阶 3。
* 菜单：圆角 12，内边距 4，条目高 28–32，选中项右侧打勾，1px 细边加柔和阴影；打开 120ms，轻微缩放（0.98→1）加淡入，缩放原点在触发器。
* 条目悬停遵循第 8 节，不额外加填充（见第 14 节决策 D）。

### 7.5 按钮

* Export 是唯一主按钮：高 32，圆角 8，字重 500；填充用强调色（待第 14 节决策 B 的对照版确认）。
* Play/Pause 为次级按钮：细边，紧凑；与声音按钮并入画布下方控制条，间距 8–12。
* 图标按钮 28 见方，命中区域不小于 28。

### 7.6 提示气泡

* 深色圆角 6，文字 12，延迟约 400ms，出现 100ms；现有 Appearance 提示保持。

### 7.7 画布外框

* 圆角 12，1px 低对比边框；浅色下加极轻的双层阴影；深色下只用边框（白色低透明度）并保证上缘与舞台可区分。
* 舞台背景比侧栏略深或略浅一档，但不得形成又一圈边框感。

### 7.8 焦点环

* 仅在键盘焦点（:focus-visible）出现：2px 强调色加 2px 偏移，圆角跟随元素；鼠标点击不出现。取代当前 Elevated 上偏重的深蓝描边。

## 8. 状态与已确认约束（不可被本文件覆盖）

以下来自协作规范，所有交互控件通用：

1. 悬停：不新增蓝色文字、蓝色底板或阴影，组件整体不透明度为 70%；保留选中态语义、禁用态与键盘焦点。shell-hierarchy-3 左栏试版例外：文字与选中底板降为 70%，图形保持常态透明度和滤镜，避免图标再次变淡。该例外待用户确认，其他控件沿用原规则。
2. 点击缩放克制且全站一致（沿用现有数值，不新增）。
3. 主题图标位置稳定；天气和场景切换无闪屏；深浅切换要核对海面与路面不闪烁。
4. 不适用的控件隐藏；跨场景设置按已确认规则沿用，场景专属项随场景。
5. 每个控件必须逐类核查：默认、悬停、选中后悬停、禁用、键盘焦点，浅深主题各一遍。

## 9. 动效（现有效果冻结）

用户于 2026-10-31 明确表示现有动效满意，不需要修改。下列原草案数值仅保留为历史提案，不作为执行目标；所有切换、主题遮罩、悬停、点击缩放、滑块与开关运动沿用当前实现。后续静态样式与结构调整也须保留这些效果，除非用户再次明确要求改变。

* 时长：微交互 100–150ms，开关、分段滑块、菜单 150–200ms；缓动用出缓动（如 cubic-bezier(0.2, 0, 0, 1)）。
* 只动 transform 和 opacity，不动布局属性；切换时不允许内容跳动。
* 开启"减少动态效果"时直接切换，不做滑动与缩放。
* 主题切换沿用已确认的从按钮中心展开的柔边过渡，不改动。

## 10. 图标

* 控件内图标统一 16、线宽 1.5，同一家族，不混用实心与线性；与相邻文字首行垂直居中。
* 能减少的图标不留；不为装饰增加图标。【参考：Linear 2026】
## 11. 对齐检查清单
* 同一面板内所有内容的左缘落在同一条竖线；所有控件右缘落在同一条竖线。
* 标签与控件文字基线对齐；图标中心与文字首行中心对齐。
* 分组间距一致（24），组内行距一致。
* 切换场景时，左栏、右栏、画布、控制条的位置不得抖动。

## 12. 反模式（禁止）

1. 浮动侧栏卡片、给每个分组套一层边框卡片。
2. 渐变、毛玻璃、重阴影、大面积纯黑或纯白。
3. 第二个强调色；用颜色代替层级。
4. 控件比画布更抢眼；为填空增加控件或说明文字。
5. 含义不明的彩色小点和角标。
6. 为"统一"而改动用户已确认的场景画面或已确认规则。

## 13. 验收与证据

验收五问（逐条给"通过 / 不通过 / 无法判断"）：

1. 第一眼看到的是画布而不是控件吗？
2. 控件按重要性分三档视觉重量（主按钮、常规控件、次要标签）吗？
3. 同类元素长得完全一样吗？
4. 临时去掉所有边框后，仅靠间距还能看清分组吗？
5. 浅色和深色的比例关系一致吗？
证据要求（每轮）：

* 同一视口、同一状态的前后对照，浅深各一套；视口至少两种（桌面宽屏、约 1100 宽）。
* 状态矩阵截图：默认、悬停、选中、键盘焦点、禁用。
* 样式变量表：每个变量的实测值、对应角色、使用位置；目标值与实测值的差异说明。
* 对比度实测（正文、次级文字、图标）。
* 切换场景和主题的录屏或中间帧，证明无抖动和闪烁。
* 如实区分"已实现""已验证""未能验证"；构建通过不等于视觉验收。

## 15. 交付轮次

1. 只读验证（已列清单）：先于任何视觉改动。
2. 第一轮：样式变量（表面、边框、字体、圆角），不改结构。
3. 第二轮：控件（分段、开关、下拉、按钮及各状态）。
4. 第三轮：画布外框与控制条，依赖结构改动已确认。
5. 原第四轮动效改造已取消：按用户最新决定保留现有动效，不调整时长、曲线、位移、缩放、透明度或主题遮罩。
每轮结束只汇报证据，等 Claude 与用户验收通过后再进入下一轮；发现需要改动本文件之外的范围时先回报。
